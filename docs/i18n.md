# Локализация фронтенда (ru + kk)

Зеркало ключевых решений из `Profy-Backend/docs/i18n-contract.md` — здесь только
фронтовая часть. При расхождении верен бэкенд-контракт.

Статус: **в работе**. `kk` ещё не включён для пользователей (см. «Выкатка»).

---

## Библиотека

`i18next` + `react-i18next`. Плюрализация — встроенные `_plural`-суффиксы i18next
(при нехватке правил для казахского — `i18next-icu`). Форматирование чисел/дат —
`Intl.*` через обёртки (`src/shared/i18n/format.ts`).

## Структура каталога

```
src/shared/i18n/
  index.ts                инициализация i18next (+ dev pseudo-locale)
  format.ts               обёртки над Intl (локаль-aware дата/число)
  locales/
    ru/<namespace>.json    источник правды по строкам
    kk/<namespace>.json     структурная копия ru + переводы
scripts/
  i18n-exclude.json       единый список путей-исключений (KZ-210)
  i18n-parity.mjs         ru ↔ kk паритет ключей        → npm run i18n:parity
  i18n-plurals.mjs        плюральные формы 0/1/2/5/11/21 → npm run i18n:plurals
  i18n-sweep.mjs          rg по всему src, кроме каталога → npm run i18n:sweep
                          npm run i18n:check = все три сразу (для CI KZ-602)
```

Неймспейсы (по областям): `common`, `auth`, `onboarding`, `assessment`,
`results`, `roadmap`, `profile`, `errors`.

**Неймспейса `admin` нет** — см. «Исключения».

**Псевдо-локаль (dev):** `?pseudo` в URL (только `import.meta.env.DEV`)
оборачивает каждую резолвнутую строку в `⟦…⟧` через post-processor i18next.
Строка без скобок на экране = незавёрнутый (хардкод) литерал.

## Ключи

- Именование: `namespace:area.element`, точечная иерархия
  (`assessment:restStop.title`, `results:riasec.R.label`).
- Строки `ru/*.json` — источник правды. `kk/*.json` обязан иметь тот же набор
  ключей 1:1 — `npm run i18n:parity` (плюрал-варианты сводятся к базе перед
  сравнением). CI подключает в KZ-602.
- Отсутствует `kk`-ключ → рендерится `ru` (`fallbackLng: 'ru'`,
  `returnEmptyString: false`). Никогда не рендерится сам ключ или пустая строка.

## Правила использования

- **Никакого пользовательского текста в JSX напрямую.** Только `t('ns:key')` или
  `<Trans i18nKey="ns:key">` (для строк с разметкой/ссылками).
- **Никакой конкатенации строк.** `t('key', { count })` + плюрализация, не
  `count + ' лет'`. Подстановки — интерполяция `t('key', { name })`.
- Даты/числа/валюты — через `src/shared/i18n/format.ts` (текущая локаль
  `ru-RU` / `kk-KZ`), не `toLocaleString()` вручную с хардкодом локали.
- **Справочники-константы** (`src/shared/config/constants.ts`,
  `src/shared/lib/sounds.ts`, `src/shared/ui/navigation/navItems.ts`):
  `*_LABELS` / `*_DESCRIPTIONS` / `*_HINTS` и `label`/`description` в
  списках-константах хранят **i18n-ключи** (`'ns:key'`), а не текст. Резолвятся
  через `t(MAP[code])` в месте использования. Коды-энумы, иконки/эмодзи и
  массивы-порядки остаются литералами (не текст). Так справочник остаётся одним
  индексом `код → ключ`, а перевод — в каталоге (тикет KZ-202).

## Форматирование чисел, дат, склонений (тикет KZ-209)

- **Склонение — только через i18next-плюрализацию.** Ключ с числом заводится
  как `key_one` / `key_few` / `key_many` / `key_other` (ru) и `key_one` /
  `key_other` (kk); в коде — `t('ns:key', { count })`. i18next сам выбирает
  форму по `Intl.PluralRules` активной локали (в `init` **нет**
  `compatibilityJSON`, поэтому работает CLDR-v4 и казахские правила).
  **Запрещено**: ручные `mod10`/`mod100`-хелперы, тернарники `n === 1 ? …`,
  конкатенация `` `${n} лет` ``.
- Число без согласуемого существительного (год поступления `2028`, «Прошли 12»,
  «+3 ещё», «~15 мин») — это просто `{{count}}`/`{{year}}` в интерполяции,
  плюральные суффиксы не нужны. Годы **не** группируются (никакого `2 028`).
- **Числа с разрядами, даты, валюты — только через `src/shared/i18n/format.ts`**
  (`formatNumber`, `formatDate`), которые берут локаль из i18next
  (`ru-RU` / `kk-KZ`). Прямой `Number.toLocaleString('ru-RU')` /
  `new Intl.*('ru-RU')` в продуктовом коде запрещён (в админке — можно, она
  `ru`-only).
- Единый источник для повторяющихся величин: возраст — `common:ageYears`
  (и `profile:meta.ageYearsUpper` для капса), класс — `profile:personal.gradeValue`
  / `profile:meta.gradeUpper`, кол-во программ — `results:programList.count`,
  задач — `roadmap:page.taskCount`, вопросов — `assessment:intro.itemCount`.
- Проверка: `npm run i18n:plurals` — резолвит каждый плюральный ключ для
  `count` = 0/1/2/5/11/21/100 в обеих локалях и падает, если какая-то форма
  вернула пустую строку или сам ключ. Подключается в CI в KZ-602.
- Пользовательских дат экраны сейчас не рендерят (`application_deadline`,
  `created_at` есть только в типах / в админке). Когда появятся — через
  `formatDate`.

## Локаль-стор и передача на бэк

- Выбор языка хранится в zustand-persist (`src/shared/store`, поле `locale`).
  Инициализация: `users.locale` (после логина) → `navigator.language` (если в
  `supportedLngs`) → `ru`.
- `src/shared/api/client.ts` — интерцептор запроса добавляет
  `Accept-Language: <locale>` на **каждый** запрос.
- Залогиненный пользователь при смене языка шлёт `PATCH /api/v1/auth/me
  { locale }`; при ошибке сети — откат UI + тост.
- `<html lang>` синхронизируется с локалью в `src/app/App.tsx`.

## Выкатка (без feature-flag)

**`kk` включён — KZ-603, 2026-09-08.** `SUPPORTED_LOCALES` в
`src/shared/store/locale.ts` = `['ru', 'kk']`; `supportedLngs` в
`src/shared/i18n/index.ts` берёт этот же список; `LOCALE_SWITCH_ENABLED`
(`length > 1`) стал `true`, поэтому `LanguageSwitcher` виден в auth-лейауте,
верхней панели и Профиль → Настройки. Откат — `revert` PR KZ-603: список
возвращается к `['ru']`, переключатель снова прячется, `kk`-контент остаётся в
БД, просто не отдаётся.

До KZ-603 `kk` физически отсутствовал в `supportedLngs` всю разработку (нет
feature-flag → частично залитый перевод недостижим), а каждый тикет
локализации обязан был не менять поведение для `ru`.

## Исключения

- **Админ-панель `/admin/*` — намеренно `ru`-only** (тикет KZ-210). Внутренний
  инструмент команды, не локализуется:
  - `src/pages/admin/**` — все экраны и компоненты админки;
  - `src/shared/ui/admin/**` — админ-примитивы (`RoleBadge`, `ChangeLogTable`,
    `AdminSectionHeading`, `RoleGatedAction`, `density`);
  - `src/shared/lib/adminRole.ts` — `ADMIN_ROLE_LABELS` /
    `ADMIN_ROLE_DESCRIPTIONS` / `REQUIRES_ADMIN_TOOLTIP` (лейблы ролей
    «Администратор»/«Оператор», тултип), видны только в `/admin/*`.

  В этих путях `t()` / `<Trans>` **не используются**, кириллические литералы —
  ожидаемы. Единый список путей-исключений — `scripts/i18n-exclude.json`
  (`globs` + пофайловые исключения). CI-гард KZ-602 читает **этот файл**, не
  дублируя пути у себя; `ChangeLogTable` там же — единственное разрешённое место
  для `new Date(...).toLocaleString('ru-RU', …)` вне `format.ts`.
- **Общие UI-примитивы работают и в админке, и в пользовательской части без
  правок.** Проверено (KZ-210): в `/admin/*` рендерятся `Button`, `Tooltip`,
  `Card`, `Spine`, `PageContainer`, `Heading` — ни один не вызывает
  `useTranslation`/`i18n`, это чистые presentational-компоненты. Примитивы,
  которые всё же зовут `t()` (`Spinner`, `PageStub`, `ErrorBoundary`,
  `NotFoundPage`, `LanguageSwitcher`, `MatchLadder`, навигационные rail'ы), в
  админке не используются, а при использовании отдавали бы `ru` (`fallbackLng:
  'ru'`, `returnEmptyString: false`). Отдельного `t()` в админ-компонентах не
  появляется.
- Dev-only аффордансы за `import.meta.env.DEV` (напр. «Автозаполнить тест» в
  `AssessmentRail`) не локализуются — в прод-сборку не попадают.
- Описания вузов/программ приходят с бэка и на первом этапе могут быть на `ru`
  даже при `locale=kk` — фронт показывает транзитную пометку по полю
  `description_locale` из ответа API (тикеты KZ-501 / KZ-502). После KZ-504
  описания переведены.
- **Разбор бэкенд-данных ≠ UI-строка.** Кириллические литералы, которыми фронт
  *сопоставляет/парсит* значения из ответа API, не локализуются: сравнение
  страны (`country === 'Казахстан'` в `results/hooks/useUniversityList`,
  `ProgramDetailPage`), словарь валют и regex разбора цен/баллов в
  `results/utils/programUtils.ts`, разбор `admission_scores_2026`
  (`extractGrantScoreRange`). Каждое такое место помечено комментарием
  «backend data / not UI copy» (тикет KZ-206).
- `src/shared/api/feedback.ts` → `REPORT_SECTIONS`: поле `labelKey` (i18n-ключ)
  использует пользовательская форма отзыва через `t()`; поле `label` (`ru`-строка)
  оставлено **только** для `ru`-only админ-экрана `AdminFeedbackPage`, который по
  политике не вызывает `t()`. Оба поля держать синхронно с `ru`-каталогом
  (тикеты KZ-206 / KZ-210).

## Глоссарий (KZ-211)

Зафиксирован и применён ко всему `kk`-каталогу. Проверка согласованности —
`npm run i18n:sweep` + грепом по терминам ниже.

| RU / понятие | KK | Комментарий |
|---|---|---|
| направление (карьерное) | **бағыт** | не `бағдар`, не `сала`; «сала» = сфера в explore-сценарии |
| профессия | **мамандық** | единообразно; `кәсіп` не используем |
| вуз (тип учреждения) | **ЖОО** | аббревиатура; конкретное «университет» → `университет` |
| ЕНТ | **ҰБТ** | всегда казахская аббревиатура |
| класс (учебный) | **сынып** | |
| школа | **мектеп** | |
| диагностика / тест | **диагностика** / **тест** | как в RU |
| сильные стороны | **күшті жақтар** | |
| точка роста | **өсу нүктесі** | не `даму нүктесі` |
| резюме (отчёта) | **түйін** | |
| вердикт | **түйін** (в roadmap), **тұжырым** избегаем | |
| RIASEC-типы | Реалистік / Зерттеушілік / Артистік / Әлеуметтік / Кәсіпкерлік / Конвенциялық | нескл. номинатив |
| уровень интереса | Әлсіз / Орташа / Айқын **көрінген** | |
| степень совпадения | Күшті / Жақсы / Ішінара **сәйкес(тік)** | |
| форматы экранов | «Ликерт шкаласы», «үштік», «жұп» | |
| обращение к подростку | 2 л. ед. ч. («сен», `-сың/-сің`), тёплый неформальный тон | как в RU |
| названия горизонтов | «1 ай», «3 ай», «12 ай», «Мақсатқа дейін» | |
| маскот (alt) | «Profy маскоты · …» | RU: «Маскот Profy · …» |

**Инвариантно** (не переводится): `RU`/`ҚАЗ` в переключателе языка,
акронимы `IELTS` / `SAT` / `TOEFL` / `GPA`, коды-энумы, канонические значения
пресетов (см. KZ-204).

## Вычитка носителем — чек-лист (KZ-211)

Первичный перевод — LLM по глоссарию выше. **Обязательная выборочная вычитка
носителем `kk`** для неймспейсов с высокой ценой ошибки (каждый ученик видит):

- [ ] `auth` — тексты ошибок, письма-подсказки, шаги регистрации, OTP
- [ ] `onboarding` — welcome, валидаторы, пресеты предметов/увлечений, «язык обучения»
- [ ] `assessment` — инструкции форматов, полюса шкал, «привалы», напоминание про
      скорость, экран похвалы/загрузки, dnd-объявления для скринридера
- [ ] `results` — заголовки секций, `interestDomain`/`scenario*`, форма отзыва,
      `programList`/`rank`/`reqKey`, inquiry
- [ ] `errors` + generic из `common` (network/unknown/required), `passwordStrength`

Быстрый просмотр (точечные правки): `common` (кроме выше), `roadmap`, `profile`.

Что проверять: род/падеж после числительных (плюрал-ключи), тон (2 л. ед. ч.,
без канцелярита), кальки с русского, термины по глоссарию, длину строк в узких
местах (бейджи, чипы, кнопки). Внесённые правки — коммитом с префиксом
`i18n(kk): native review — <ns>`.
