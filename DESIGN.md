# Profile — интерфейс интеграционной ветки

Утверждённый редизайн: спокойная светлая основа, тёмно-зелёные действия,
оранжевые акценты и лиловые второстепенные блоки. Тот же язык применяется
на лендинге, входе, в диагностике и кабинетах ученика, психолога и администратора.

## Источники стилей

- `src/shared/ui/redesign/redesign.css` — токены `.redesign`, кнопки, бренд,
  ссылки, фокус и общие элементы.
- `journey.css`, `checkpoints.css`, `student.css`, `psychologist.css`,
  `admin.css` в той же папке — композиции соответствующих экранов.
- `src/styles/theme.css` — базовые токены и ещё используемые общие компоненты.
  `.redesign` связывает их семантические переменные с новой палитрой.
- `src/styles/print.css` — отдельная светлая палитра и правила печати.

Новый экран должен подключать подходящую оболочку и существующие компоненты,
а не копировать шапку, переключатели или карточки. Цвета берутся из токенов;
исключение — печатные документы, где фиксированная светлая палитра намеренна.

Шкала радиусов, токены цвета и правило про `!important` ниже действуют для
`src/shared/ui/redesign/*.css` и `src/pages/landing/redesign.css`. CSS экранов
теста (`src/pages/assessment/**/*.css`) на них ещё не переведён.

`!important` в этих файлах не нужен. Сбросы `.redesign` для `p`, `h1–h3` и `a`
имеют нулевую специфичность и уступают любому правилу компонента, а
Tailwind-утилиты лежат в слое и проигрывают любому правилу вне слоя.
Единственное исключение — отключение анимаций при `prefers-reduced-motion`.
Если правило «не применяется», причина обычно в inline-стиле компонента или в
`!`-утилите в разметке (`!bg-transparent`, `!p-6`): такую утилиту побеждает
только она сама, поэтому убирать её нужно из разметки, а не перебивать в CSS.

| `--rd-ink` | `#203a30` | Заголовки и основной текст |
| `--rd-pine` | `#164d3e` | Основное действие, активная навигация |
| `--rd-sage` | `#eaf1e8` | Спокойная вторичная поверхность |
| `--rd-orange` | `#ef985f` | Небольшой тёплый акцент |
| `--rd-peach` | `#fbe9d9` | Фон тёплого акцента |
| `--rd-purple` | `#8063ad` | Вторичный акцент, клавиатурный фокус |
| `--rd-lilac` | `#eee8f5` | Фон вторичного акцента |
| `--rd-line` | `#e1e7dc` | Разделители и границы |
| `--rd-orange-deep` | `#945c36` | Оранжевый для текста и иконок (AA на `--rd-peach`) |
| `--rd-moss` | `#698765` | Приглушённый зелёный акцент |
| `--rd-pine-solid` | `#164d3e` | Тёмная брендовая плоскость, тёмная в обеих темах |
| `--rd-on-pine-solid` | `#ffffff` | Текст на `--rd-pine-solid` |

`--rd-orange` не используется для мелкого текста на светлом фоне — для текста
и иконок есть `--rd-orange-deep`. Не обозначать смысл только цветом: у статуса
остаются подпись и при необходимости иконка.

Тени и затемнение — тоже токены: `--rd-shadow` (карточки), `--rd-shadow-up`
(липкая панель действий), `--rd-shadow-overlay` (диалог), `--rd-backdrop`
(фон под диалогом). Хексы живут только в блоках токенов `redesign.css`;
в правилах компонентов — `var(--rd-*)` или `color-mix()` от них.

`.dark .redesign` задаёт вторую палитру: тёмно-зелёный фон, светлый текст,
приглушённые цветные поверхности и светлую основную кнопку. Не добавлять
отдельные `dark:`-ветки в разметку. Печатный лист всегда светлый, включая
заголовки и диаграммы, независимо от темы приложения.

## Типографика и композиция

Onest используется для интерфейса, заголовков и числовых показателей;
IBM Plex Mono — для кодов и технических данных. Обе семьи поддерживают
кириллицу. Крупные счётчики не наследуют разреженный трекинг подписей.

Использовать существующие именованные классы и компоненты типографики.
Не добавлять произвольные размеры в JSX. На экране один главный заголовок;
длинные русские и казахские названия переносятся внутри доступной ширины.

Размеры шрифта в redesign-CSS — только из шкалы `--text-rd-*` в
`src/styles/tailwind.css`:

| Токен | Размер | Где |
|---|---|---|
| `--text-rd-label` | 12 px | подписи, метки, бейджи, шапки таблиц, подсказки к полям |
| `--text-rd-ui` | 14 px | кнопки, навигация, вкладки, ячейки, вторичный текст карточек |
| `--text-rd-body` | 16 px | основной текст, поля ввода |
| `--text-rd-lead` | 18 px | вводный абзац, крупные факты |
| `--text-rd-title` | 20 px | заголовок карточки |
| `--text-rd-heading` | 24 px | заголовок блока или диалога |
| `--text-rd-display` | 30 px | заголовок раздела, цифры статистики |
| `--text-rd-display-lg` | 40 px | заголовок секции лендинга |
| `--text-rd-hero` | 36–66 px | h1 лендинга |
| `--text-rd-page` | 30–40 px | заголовок страницы, растёт с шириной |

- Меньше 12 px текста нет. Абзац, который читает ученик, — 16 px; 14 px —
  для элементов управления и второстепенных строк в плотных карточках.
- Трекинг заголовков не уже `-0.02em`: при более узком кириллица и казахские
  ә, ғ, қ, ө слипаются. Исключение — латинский логотип.
- Мобильная версия не уменьшает текст ниже шкалы: если блок не помещается,
  меняется раскладка, а не кегль.
- Графику, набранную шрифтом (логотип, глифы-иконки, монограммы-заглушки),
  помечают `/* type-exempt: причина */` сразу после объявления.
  `npm run lint:typography` проверяет это вместе с JSX, а в CSS экранов теста,
  который на шкалу ещё не переведён, — только нижнюю границу 12 px.

- Радиусы — только из шкалы, не числом:

  | Токен | Значение | Где |
  |---|---|---|
  | `--rd-radius-sm` | 8 px | чипы, бейджи, вкладки внутри сегмента, плитки до 32 px |
  | `--rd-radius-md` | 12 px | кнопки, поля, иконки-плитки, вложенные карточки |
  | `--rd-radius-lg` | 20 px | карточки, панели, выпадающие меню, диалоги |
  | `--rd-radius-xl` | 28 px | крупные плоскости: шапка отчёта, промо-блоки лендинга |

  Капсулы — `var(--radius-pill)`, круги — `50%`. На узком экране крупная
  плоскость спускается на шаг (`xl` → `lg`); вложенный элемент берёт шаг
  меньше, чем его контейнер.
- Основной разделитель — тонкая граница. Мягкая тень допустима для больших
  поверхностей, но не нужна каждому вложенному элементу.
- Высота карточки определяется содержимым. Маскот не должен создавать
  пустой ряд над текстом или растягивать соседний блок.
- Данные таблицы, фильтр, счётчик и экспорт должны описывать один и тот же
  срез. Демонстрационные данные существуют только в DEV-галереях.

## Маскот и движение

Утверждённые прозрачные PNG находятся в `public/mascot/redesign/`.
Функциональные состояния общего `Mascot` также используют эти изображения.
Не возвращать старый фон, наклон, обрезку хвоста или геометрию глаз прежнего
персонажа. Прозрачность и соответствие поз описаны в `public/mascot/README.md`.

Маскот сопровождает вход, паузы, ожидание и завершение. Он не оценивает
ответы ученика. Шкалы ответов и их поведение сохраняются: редизайн меняет
окружение, а не смысл и механику диагностики.

Движение короткое и вспомогательное. Все новые анимации отключаются при
`prefers-reduced-motion: reduce`; не использовать увеличение, которое
обрезается контейнером или перекрывает соседние элементы.

## Общие композиции

- `JourneyShell` — бренд, одна группа языка/темы и ссылка пропуска к контенту.
- `JourneyCheckpoint` — короткие переходы, паузы, ошибка подготовки и 404.
- `ResultLoadingView` — один статус ожидания; `fullPage` добавляет оболочку,
  встроенный вариант не дублирует шапку.
- `PrintMasthead` — единая шапка ученического и административных отчётов.
  Печатные таблицы сохраняют строки целиком. CSS задаёт повторение шапки;
  Safari может не повторять её на следующих листах (ограничение WebKit).

## Проверка изменений

Проверять светлую и тёмную темы, RU и KK, узкий экран и рабочий стол,
клавиатурный фокус, длинный текст и пустые/ошибочные состояния. Новые тексты
добавляются одновременно в оба каталога, по контракту `docs/i18n.md`.

Обязательные команды: `npm run typecheck`, `npm run lint`,
`npm run i18n:check`, `npm run build`. После удаления кода — `npm run knip`.
PDF проверяется настоящей печатью браузера с выключенным фоном, а не только
экранным предпросмотром.

DEV-галерея `/design/finishing` показывает переходы, загрузку, ошибки и
печатные формы на вымышленных данных. В production этот маршрут отсутствует.
