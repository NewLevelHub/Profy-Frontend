# Handoff: Веб-адаптация главных экранов Profy (Главная, Результаты, Профиль)

## Overview
Три главных экрана приложения Profy (профориентация для детей и подростков 6–18 лет) были переработаны с мобильной раскладки на полноценный веб-формат: постоянный боковой сайдбар, многоколоночные сетки, использование освободившегося горизонтального пространства. Сохранён фирменный визуальный язык Profy (фиолетовый + оранжевый, градиентные hero-блоки, круглые прогресс-индикаторы, скругления, мягкие тени). Из "Результатов" убраны процентные показатели совпадения с профессиями (чтобы не создавать ложное ощущение точного алгоритмического решения за ребёнка) и добавлена кнопка запроса деталей по направлению.

## About the Design Files
Файл `design-reference.dc.html` — это **HTML-прототип для визуальной и поведенческой сверки**, а не код для копирования. Задача разработчика — воссоздать эти экраны в существующем стеке проекта (React 18 + TypeScript + Tailwind CSS v4 + React Router + Zustand + TanStack Query), используя уже принятые в кодовой базе паттерны компонентов, хуков и стилей, а не переносить HTML/инлайн-стили напрямую.

## Fidelity
**Высокая точность (hifi)** — цвета, типографика, отступы, скругления и тени финальные. Копии кнопок/бейджей/карточек должны быть пиксель-в-пиксель близки к прототипу. Эмодзи в прототипе — временная заглушка (по ТЗ маскоты появятся позже); при вёрстке можно оставить emoji как есть или согласовать замену на `lucide-react` иконки там, где это чисто утилитарные значки (например ⏻ выход, ↻ обновить), сохранив декоративные emoji (🏠📊👤🎯 и т.п.) без изменений до появления маскотов.

### Рекомендации по стеку
- Вёрстка — Tailwind-утилитами (не инлайн-стилями, как в прототипе). В прототипе все значения инлайновые только потому, что это ограничение среды генерации дизайна — в проде используйте существующие `theme.css`/`tailwind.css` токены (см. раздел Design Tokens — они уже почти 1:1 совпадают с переменными `--brand`, `--accent`, `--radius-*` и т.д. из вашего `theme.css`).
- Маршруты: `/` (Главная), `/results` (Результаты), `/profile` (Профиль) через React Router; активный пункт сайдбара — по `useLocation()`/`NavLink`.
- Состояние "выбранное направление / открытая модалка", "вкладка Стэппер/Квест-карта", "отмеченные направления как понравившиеся" — локальный стейт компонента (`useState`) достаточно; если "отмечено" должно сохраняться между сессиями — вынести в Zustand store (например `useAssessmentStore`) и синхронизировать с бэкендом через React Query mutation.
- Данные (профессии, интересы, дорожная карта, зоны внимания) — приходят с бэкенда через React Query (`useQuery`), а не хардкодятся, как в прототипе.

## Screens / Views

### 1. Главная (Home)
**Purpose:** показать прогресс прохождения диагностики и дать быстрый доступ к результатам/профилю.

**Layout:**
- Общий layout: `flex`, sidebar 240px fixed + content area `flex:1`, скролл в content area.
- Content area: `max-width:1260px`, центрирован, padding `44px 48px 80px`.
- Приветствие: avatar 52px circle (gradient) + заголовок 28px/800 + подзаголовок 15px/500, gap 16px, margin-bottom 28px.
- Hero "Твой путь": full-width карточка, `border-radius:22px`, padding `36px 40px`, `display:flex;align-items:center;gap:28px`, содержит: круговой прогресс-индикатор 88px (внешнее кольцо — залитый круг, внутренний круг 70px с текстом "8/8"), заголовок+подзаголовок белым, CTA-кнопка справа (белая пилюля, фиолетовый текст).
- Под hero — grid 2 колонки (gap 20px): карточки быстрого перехода "Результаты" и "Профиль" (иконка в цветном квадрате 48px + заголовок + подпись), кликабельны целиком.
- "Дорожная карта": заголовок + сегмент-переключатель (пилюля с двумя вкладками "Стэппер"/"Квест-карта") справа.
  - Стэппер: карточка с `grid-template-columns:repeat(8,1fr)`, соединительная линия — abs-positioned div поверх которой z-index:1 стоят круги 44px (зелёный, ✓) + подпись под каждым.
  - Квест-карта: тот же grid, но круги 52px с `border-radius:16px`, градиентная фиолетовая заливка, элементы чередуются по вертикали (zig-zag через translateY, чётные/нечётные ±18px) для игрового эффекта.

**Design tokens used:** brand gradient `linear-gradient(135deg,#7C3AED,#5B21B6)`, success `#22C55E`, surface `#FFFFFF`, page bg `#F5F3FF`, sidebar bg `#F0ECFF`.

### 2. Результаты (Results)
**Purpose:** показать профиль склонностей, резюме и рекомендованные направления без навязывания точного "% совпадения".

**Layout:**
- Заголовок 30px/800 + подзаголовок.
- Hero "Лучшее совпадение": градиентная карточка (как на Главной), метка "🎯 ЛУЧШЕЕ СОВПАДЕНИЕ" (без цифр!), название направления 30px, описание, CTA "Подробнее →".
- "Резюме": карточка на лавандовом фоне `#EDE9FE` (не белая — визуально отличается от "обычных" карточек), текст-абзац.
- "Сильные стороны": ряд пилюль (`flex-wrap`), каждая — круглая цветная иконка 30px (пастельный фон, чередуется по палитре: rose/amber/blue/green) + текст.
- "Подходящие профессии": grid 3 колонки, gap 18px. Каждая карточка:
  - кликабельна целиком (курсор pointer, hover — подъём + усиленная тень) — **открывает модальное окно с деталями** (причины подходимости + список конкретных профессий с описанием);
  - содержит: иконку (26px emoji), заголовок, описание, тег-пилюли (роли), кнопку **"Подходит ли мне это направление?"** (toggle: при клике превращается в заливку с "✓ Отмечено" — состояние должно сохраняться на сервере через мутацию, если фича "избранное направление" должна переживать сессию) + текстовую кнопку "Подробнее о направлении →" (тоже открывает ту же модалку).
  - **Без числового % совпадения** — это осознанное решение продукта, чтобы не создавать ложное чувство алгоритмической точности у ребёнка.
- Модалка направления: overlay `rgba(30,27,75,.45)`, карточка `max-width:560px`, `border-radius:24px`, содержит иконку/название/описание, список "Почему подходит" (bullet list), список профессий (name+desc каждая), кнопку toggle "Подходит ли мне".
- Двухколоночный блок (`1.3fr 1fr`): слева "Твои интересы" (горизонтальные прогресс-бары, градиентная заливка, % — это НЕ совпадение профессии, а собственная метрика интересов, оставлена); справа "Стиль мышления" (grid 2×2 карточек с иконкой/подписью/%) + "Зоны внимания".
- **"Зоны внимания" — список переменной длины (1–6+ пунктов)**: реализован как карточка с внутренними строками (`flex-direction:column;gap:1px`), каждая строка — одинаковый padding/typography. Контейнер просто растёт вниз при добавлении пунктов, ничего вокруг не сдвигается и не обрезается (никаких фиксированных высот/overflow:hidden на этом блоке).

### 3. Профиль (Profile)
**Purpose:** просмотр/редактирование личных данных, управление настройками и выходом.

**Layout:**
- Карточка профиля (full width): avatar 72px circle (gradient) + имя 20px/800 + email + бейдж возрастной группы (пилюля, справа через `margin-left:auto`).
- Grid ниже: `repeat(auto-fit, minmax(280px,1fr))` — на узких экранах адаптивно уходит в 1–2 колонки (**важно**: раньше была жёсткая 3-колоночная сетка, из-за которой на ~900px тексты обрезались — сейчас именно auto-fit решает эту проблему, не убирайте его).
  - "Личные данные": grid 2×2 полей + пункт "Изменить" (заголовок и ссылка — flex с `gap`, `flex-wrap:wrap`, чтобы не наезжали друг на друга на узких колонках).
  - "Предметы": пилюли "Даются легко" (зелёные) / "Даются сложно" (оранжевые) — **без эмодзи-иконки в заголовке подсекции** (убраны по правкам ревью).
  - Третья колонка: карточка "Звуковые эффекты" (toggle-switch) сверху, затем **outline-кнопка** "↻ Начать тестирование заново" (не залитая — это деструктивное/вторичное действие, не основной CTA) и текстовая ссылка "Выйти из аккаунта" снизу.

## Interactions & Behavior
- Sidebar-навигация переключает экран без перезагрузки (React Router).
- Сегмент "Стэппер/Квест-карта" — чисто визуальный переключатель отображения одних и тех же данных дорожной карты.
- Клик по карточке профессии или по кнопке "Подробнее о направлении →" открывает модалку; клик по фону модалки или ✕ — закрывает. Клик по внутренней кнопке toggle внутри карточки должен вызывать `stopPropagation`, чтобы не открывать модалку одновременно.
- Кнопка "Подходит ли мне это направление?" — двухпозиционный toggle (не отправляет форму, не ведёт на другую страницу) — по клику меняет вид на заливку + "✓ Отмечено".
- Hover на кликабельных карточках профессий — лёгкий подъём (`translateY(-3px)`) + усиление тени, сигнализирует кликабельность.
- Все интерактивные элементы — хотя бы 40px по высоте (уже соблюдено).

## State Management
- `activeScreen`: производится из роута (React Router), не нужен отдельный стейт.
- `roadmapMode`: 'stepper' | 'quest' — локальный UI-стейт, можно `useState`.
- `selectedProfessionId`: number | null — локальный стейт экрана "Результаты" (модалка).
- `interestedProfessionIds`: Set<number> — если это должно сохраняться между визитами, перенести в Zustand-store + синхронизировать с бэкендом (React Query mutation при toggle, invalidate на нужный query).
- Данные профессий/интересов/дорожной карты/зон внимания — приходят через `useQuery` (React Query), не хардкодить.

## Assets
Все иконки в прототипе — emoji Unicode (плейсхолдер до появления маскотов направлений). Ни один SVG/растровый ассет не использовался. При переносе на `lucide-react` учитывайте, что часть emoji несёт продуктовый/эмоциональный смысл (🎯🌿💪👋) и, вероятно, должна остаться emoji/маскотами, а не превращаться в нейтральные line-иконки.
